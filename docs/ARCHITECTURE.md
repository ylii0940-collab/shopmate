# ShopMate 技术架构

浏览器UI → 导购编排器runShoppingTurn → 共享领域引擎 → 演示商品适配数据。

本地可选路径：浏览器 → 同源/api/analyze → 模型抽取JSON → 合法性检查与规则回退 → 前端合并历史购物偏好 → 程序执行商品筛选与后续动作。

## 状态

使用独立的shopmate-v2浏览器存储键，不读取旧版直播运营数据。保存最多12个对话、每个对话最近40条消息、商品对比列表、按市场区分的购物车和最近1000条事件。切换市场会重置当前偏好；新对话保留购物车。旧消息按原市场显示。

## 工具与决策

- understand_request：解析需求，合并明确条件。
- search_products：执行硬约束并计算匹配分。
- compare_products：查询目录里的真实演示字段。
- get_product_details：核验商品规格与颜色。
- store_policy / get_delivery_estimate：返回演示政策与时效。
- verify_constraints：验证预算、商品来源、库存、市场与必要特性；推荐检查失败时不展示结果。

以上是程序编排的可执行步骤，不是模型的隐藏思维链。续航标称、配送时效等字段只取自商品数据，不由模型编造。

## 真实店铺接入

需要替换商品适配器为授权店铺的商品、规格、价格、市场与库存数据；Product与Variant分开建模。真正的购物车由店铺接口创建，结账URL由店铺返回；用户在店铺页完成地址、运费、税费和支付。本项目的虚构variant ID不能直接用于真实结账。

密钥仅通过本地服务环境变量读取，不放进前端。模型请求超时18秒，浏览器22秒；失败后使用规则结果。服务绑定127.0.0.1并限制同源分析请求。

当前静态托管只运行离线规则和浏览器状态；没有真实商家、支付或模型密钥服务。

## v2.1 搜索策略模块

导购recommend与策略页共用executeSearch。搜索模块独立于UI，返回通道命中、过滤审计、初排与最终排序；agent把检索诊断摘要存进消息。策略页不影响导购策略，点击应用后复制策略和权重到浏览器状态并开始新对话。

新增search_results、search_impression、product_clicked、product_detail_closed事件；购物车行保存搜索来源，漏斗仅在本地保留窗口关联。事件上限升级为1000条，旧对话仍可恢复，旧事件不伪造搜索来源。IntersectionObserver只负责曝光观察，不上传行为。

导购消息可点击“查看这次搜索策略”复盘当时的结构化条件、策略、权重与市场。详细结果按当前演示目录重新计算，不是历史库存快照。

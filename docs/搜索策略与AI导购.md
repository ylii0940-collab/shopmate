# ShopMate 搜索策略产品作品 v2.1

## 要解决的问题

用户只有预算与用途，不知道具体型号。直接按评分排，可能不能体现用途和可购买条件；只增加聊天功能，也不能证明选购效率改善。

产品主线是消费者导购，策略页负责解释和验证同一个导购背后的商品选择逻辑。不是直播、留资或商家运营项目。

## 如何体现策略产品能力

| 工作 | 可以操作的证据 |
| --- | --- |
| 定义目标与人群 | 策略决策页列出业务目标、明确预算与用途的人群、主指标与护栏 |
| 定位链路问题 | 链路分析显示原始表达、归一、召回通道、过滤原因、每项得分及排名变化 |
| 设计策略 | A只按评分，B使用用途和供给适配，C增加同品牌惩罚；相同查询和硬约束下对照 |
| 验证效果 | 140条固定标注样本的离线指标和逐条案例，不假造线上效果 |
| 做取舍与迭代 | 策略决策按当前得分自动给出证据限制和退化案例；列出消融与独立评估计划 |
| 设计线上实验 | 明确分桶、主指标、MDE/样本量预注册、分层、护栏、扩量与回滚条件，状态为未执行 |

## 价值模型与预测模型的区别

在本电商场景，用户价值是更快找到合适商品并完成可靠购买；商家价值是有效成交与减少误购；平台价值还要兼顾信任和长期回访。点击、聊天时长只是行为信号，不等于这些价值本身。

当前没有训练预测模型。策略分是透明规则特征加权，不是pCTR、pCVR或预期GMV，也不代表真实满意度。未来有足够曝光与订单事实后，才能训练和校准预测，再用线上随机实验检验价值目标。

## 当前执行的搜索链路

1. NFKC与空格归一，有限拼写/别名改写：headphons、耳麦、蓝牙喇叭、降躁、ANC、数字+刀。
2. 解析市场、预算货币、品类、子品类、品牌、必要特性与软偏好；合并多轮条件。
3. 关键词、品类、属性标签、品牌通道合并去重，泛需求允许浏览兜底。仅在200款合成商品内直接匹配。
4. 按市场、库存、预算、品类、商品类型、必要特性和品牌过滤；记录全部失败原因。
5. 评分优先A或需求匹配B初排。B默认权重38/22/15/15/10，预算适配中心为预算的78%，这是需验证的启发式假设。
6. C采用贪心品牌多样性：已有同品牌每款扣12分，再选下一款；明确要求便宜或续航优先时，不让重排覆盖用户指定顺序。
7. 输出Top3，来源、预算、库存、市场和特性再次检查；无结果不放宽硬约束。
8. 商品卡实际进入视口再记录曝光；互动和加购保留searchId，结账按购物车来源关联。

## 真实限制

召回没有索引或向量模型；无完整拼写纠错和开放域实体理解。评估为规则生成的封闭小样本，不是盲评或独立大规模数据集。浏览器漏斗不能代表全站用户，结账预览不能当订单，品牌数增加不能当转化提升。

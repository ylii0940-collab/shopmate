# ShopMate · 国际电商导购助手（v2.1 · 200件商品版）

面向消费者的购物助手：说出需求 → 理解预算与偏好 → 筛选推荐 → 比较与追问 → 确认商品规格 → 购物车 → 结账交接预览。

## 运行

需要 Node.js 22+，无需安装 npm 包，无需 API Key。

```sh
node server.mjs
```

打开 http://127.0.0.1:8530 。桌面用户可双击“启动ShopMate.command”；旧“启动LivePilot.command”也兼容启动新版。

## 主要功能

- 购物助手：首页直接输入需求，支持中文、英文、西班牙语和印尼语的有限规则抽取。
- 多轮上下文：记住预算、品类与关注点；支持“比较前两款”“哪款续航更长”“便宜一点”“预算改成60美元”“换成音箱”。
- 约束推荐：先检查市场、库存、预算、品类 / 子品类和必要特性，再进行可解释排序。
- 规格比较：价格、续航、重量、库存、配送与政策；缺失字段显示未提供。
- 规格确认：颜色未给出时先询问，确认后才加入购物车。
- 购物车：商品 + 颜色 + 市场去重、数量变更、库存上限、移除。
- 结账交接：重算购物车并导出包含商品、规格、数量、币种和小计的交接单。
- 对话历史：刷新恢复，新对话重置偏好并保留购物车。

新增“搜索策略”入口，与消费者导购共用同一套检索排序引擎。

## 搜索策略产品能力

进入“搜索策略”，依次查看链路分析、策略对照、离线评估、行为漏斗、策略决策。

- 需求归一：有限纠错与别名规则，抽取预算、品类、品牌和硬约束。
- 多路候选：关键词、品类、属性、品牌及泛需求兜底合并去重，逐商品展示召回来源和全部过滤原因。
- 三套策略：A评分优先、B需求匹配、C品牌多样性；可调五项权重并应用到新导购对话。
- 离线验证：140条固定查询、合成规则0–3级标注、nDCG@3、P@3、召回覆盖、约束检查和无结果判断。
- 行为漏斗：导购真实操作的视口曝光、商品交互、成功加购和结账预览，按搜索来源关联；分析试跑不计入。
- 策略决策：当前策略对照基线的得分变化、退化案例、优先级、假设与线上实验计划。

所有数值由代码计算；没有真实交易、随机分流、显著性或收益结论。页面如实展示当前评估结果。标注包含合成属性规则，与排序特征相关，不能作为独立人评或业务收益证据。

```sh
node scripts/evaluate.mjs
```

完整评估结果输出到`reports/evaluation.json`。当前多路召回为小目录内直接匹配，不使用向量库或训练排序模型。

## 实现

- `dist/app.mjs`：消费者界面、对话、目录、对比、购物车与结账预览。
- `dist/agent.mjs`：固定流程的导购编排器、商品指代和连续追问。
- `dist/engine.mjs`：需求解析、偏好合并、约束推荐、比较、购物车和交接校验。
- `dist/search.mjs`：召回、硬过滤、初排、品牌重排、离线评估与行为漏斗。
- `dist/strategy-ui.mjs`：策略分析、对照与决策界面。
- `dist/eval-data.mjs`：固定评估查询与作者相关性标注。
- `dist/data.mjs`：200件演示商品、规格、颜色与4个市场配置。
- `dist/art.mjs`：原创商品SVG示意图。
- `server.mjs`：本地静态服务与可选模型抽取代理。

默认规则编排；本地设置 MODEL_BASE_URL / MODEL_NAME / MODEL_API_KEY 后，可使用OpenAI-compatible接口辅助理解单轮需求。模型失败回退规则。商品、规格、价格和购物车处理由程序执行，不允许模型直接生成交易事实。

```sh
cp .env.example .env
# 本地编辑供应商配置，勿提交密钥
node --env-file=.env server.mjs
node --test tests/*.test.mjs
```

## 数据与能力边界

商品、价格、库存、配送、政策和参数均为模拟数据。汇率固定；标称续航不是同条件实测，耳塞包含充电盒。尚未接入真实Shopify商品、购物车、订单或支付。当前结账只生成交接单，不收集地址或付款资料，不下单、不收款。真实店铺接入后，才能创建真实购物车并跳转托管结账页。

静态在线版使用浏览器localStorage；可选模型代理只在本地Node服务中可用。默认不是模型自主规划工具循环的ReAct，而是可验证的流程式导购Agent。
